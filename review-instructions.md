# Инструкция для AI-ревьюера

## 1. Цель

Провести код-ревью проекта (TODO-приложение на чистом JavaScript) на соответствие принципам Clean Code. Твоя задача — найти проблемы, которые не отлавливает ESLint, и объяснить, как их исправить.

## 2. Границы (Что проверять и чего не трогать)

- **Что проверять:** Файлы `app.js`, `index.html`, `style.css`.
- **Что оценивать:** Мёртвый код, дублирование логики или обработчиков, понятность имен переменных и функций, комментарии (пересказывающие код vs объясняющие причину), длинные функции.
- **Чего НЕ делать:**
  - Не редактируй файлы, только анализируй.
  - Не предлагай переписать проект на React/Vue/TypeScript.
  - Не придирайся к форматированию (отступам, кавычкам) — за это отвечает Prettier.
  - Не ищи синтаксические ошибки — за это отвечает ESLint.

## 3. Критерий готовности

Ревью завершено, когда все файлы проанализированы, проблемы сгруппированы по заданным категориям, и сформирован итоговый отчет.

## 4. Формат вывода

Создай файл `review-report.md` на **русском языке**.
Сгруппируй замечания по следующим категориям:

1. Мёртвый код
2. Дублирование (логики/обработчиков)
3. Имена переменных и функций
4. Комментарии
5. Длинные функции

Для каждого найденного замечания укажи:

- **Место в коде:** (например, `app.js: строка 45`)
- **Проблема:** (что именно не так с точки зрения Clean Code)
- **Условие проявления:** (когда это выстрелит или помешает)
- **Способ проверить исправление:** (как убедиться, что после рефакторинга всё работает)
